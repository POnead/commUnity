## Findings

### QA-R01 — Modal stayed open across route navigation (High, Functional)
- Observed: opened the calendar "Event details" dialog, then clicked the sidebar "Overview" link. Hash changed to `#/resident/dashboard`, the dashboard rendered behind it, but the event dialog remained open as an overlay. `modalState` is global and was not cleared on route change.
- Impact: a screen reader or keyboard user is trapped in an unrelated dialog after ordinary navigation; the new page is obscured until they close it manually.
- Fix applied: in the `hashchange` handler, clear `modalState` together with `permissionDrafts` whenever the destination actually changes (`app/main.mjs`). Real modals opened on the new page still work; forced-password and face-gate flows re-establish their own modal in `render()`.
- Verified: open event dialog → click Overview → dialog gone, dashboard visible; reopening dialogs and Escape still work.

### QA-R02 — Empty-state copy contradicted the resolved report below (Low, UX/Copy)
- Observed: on My reports with one resolved report, the active table showed "No concerns in this view / When a report is submitted, it will appear here." while "Resolved concerns · 1 marked as addressed" was rendered immediately below.
- Fix applied: `reportRows` now takes an optional `emptyHint`; `reportsPage` supplies "Resolved ones are listed below." when a resolved section exists, and the heading changes to "No active concerns".
- Verified: My reports now reads "No active concerns / Resolved ones are listed below." above the resolved row.
