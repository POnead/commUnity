## Finding

### QA-AD01 — "View report" did nothing for the administrator (High, Functional)
- Observed: on `#/administrator/reports`, clicking either "Road damage" or "View" set `selectedReportId` but the list re-rendered unchanged: no detail view, no modal, no URL change, no console error. The same no-op occurred for "View report" in administrator notifications.
- Root cause: `openReport()` (`app/main.mjs`) sets `selectedReportId` and renders; `reportsPage()` (`app/views.mjs`) returned `administratorReportsPage()` before its `selectedReportId` branch, and `administratorReportsPage()` never reads the selection. Resident and official roles took the detail branch correctly.
- Fix applied: moved the `selectedReportId` / `reportDetail(selection, role)` check ahead of the administrator early return in `reportsPage()`. The existing detail view already supports administrator (priority form, map link, status history, "Back to reports").
- Verified after reload: `View` opens "Road damage" detail (R-0001) with `Concern priority`, `Status history`, and `Back to reports`; back returns to the filtered list; notification "View report" also opens detail. Lighthouse on both list and detail: Accessibility 100, zero failures.
